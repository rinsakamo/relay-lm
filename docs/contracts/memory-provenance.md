# MEMORY Provenance Contract

This document is the canonical product authority for RelayLM `v1` MEMORY temporal provenance, stable logical identity derivation, deterministic Markdown projection, and provenance carriage into retrieval.

MEMORY text is portable presentation content. Machine-relevant currentness and lineage are represented only by typed RelayLM metadata derived from canonical State/Event authority.

## Temporal authority

A retrievable MEMORY semantic unit has one typed temporal scope:

- `current` — the unit is classified as current authority relative to its declared sources;
- `historical` — the unit is classified as historical relative to its declared sources;
- `unknown` — RelayLM has no typed current/historical classification for the unit.

`unknown` is first-class. RelayLM must not infer currentness merely because a MEMORY entry is recent, fluent, or present in the current Markdown projection.

A `current` or `historical` classification is valid only when explicit typed provenance is present. Unknown MEMORY may remain readable without provenance.

## Provenance sources

Typed provenance may reference only canonical authority roots supported by the product contract:

- `event` — an Event identifier that resolves in canonical Event authority;
- `state` — a State identifier that resolves in Canonical State.

A source reference must be non-empty. Source sets are canonicalized by `(kind, reference_id)` and must not contain duplicates.

Model-authored source claims are proposals, not authority. RelayLM validates every proposed source against the canonical Event/State inputs supplied to projection.

## Stable identity derivation

When every proposed source resolves, RelayLM derives a canonical identity basis from:

```text
temporal_scope
+ sorted typed source references
```

Heading and MEMORY prose are presentation text and do not define the logical provenance identity.

The identity basis is deterministically serialized and hashed. RelayLM derives stable versioned `memory_id` and `derivation_id` values from that digest.

A typed identity is emitted only when the resolved identity basis is unique within the projection. If sources are missing, unresolved, or the same identity basis is duplicated in the projection, the affected unit remains readable but is not promoted to classified typed authority.

## Deterministic MEMORY projection

RelayLM projects semantic MEMORY units to portable Markdown deterministically.

For each unit:

- heading whitespace is normalized for presentation;
- model-authored RelayLM metadata control lines are removed outside fenced code blocks;
- valid typed metadata is generated by RelayLM, never trusted from model prose;
- classified units carry machine-readable temporal scope, stable ids, and typed sources;
- unclassified units remain ordinary readable Markdown.

Resolved units are ordered deterministically by derived identity. Units without a derived identity use deterministic presentation ordering.

The projection always separates human-readable MEMORY text from RelayLM-generated metadata. A model cannot mint authoritative `relaylm-memory` metadata by writing a look-alike comment into its content.

## Retrieval carriage

Retrieval may carry the typed temporal authority attached to a MEMORY unit, but retrieval does not invent or upgrade provenance.

In particular:

- an unclassified/unknown unit stays unknown merely because it was retrieved;
- ranking does not change `current` to `historical` or vice versa;
- provenance identifiers and source lineage are carried as metadata, not reconstructed from natural-language claims;
- consumers may use the typed temporal distinction according to their own semantic contracts without rewriting the provenance root.

## Failure and conservative behavior

RelayLM fails closed on classification, not on readability.

If a proposed typed lineage cannot be validated, RelayLM preserves the readable MEMORY text where otherwise valid but withholds classified provenance. It does not silently substitute a nearby State/Event, infer a source from prose, or treat unresolved lineage as current authority.

## Ownership boundaries

The MEMORY provenance owner owns:

- typed MEMORY temporal scope;
- typed Event/State provenance references;
- canonical provenance identity derivation;
- deterministic provenance metadata projection;
- carriage of that metadata into retrieval.

It does **not** own:

- Event or State lifecycle and canonical contents;
- crystallization proposal generation;
- MEMORY semantic ranking/relevance policy;
- persistence file I/O;
- contradiction resolution between MEMORY and current State;
- actual-model evaluation or calibration evidence.

> MEMORY prose may be useful without being current authority; classified currentness requires validated typed lineage.
